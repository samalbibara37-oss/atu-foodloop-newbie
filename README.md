# FoodLoop ATU

**Автор: Самал Бибара. Команда: newbie.** Рабочий MVP трека 1: цифровой учёт пищевых отходов университетского комплекса.

Сотрудник записывает взвешивания, проверяющий принимает или возвращает месячный отчёт, руководство получает подтверждённый реестр, диаграммы и Excel. Есть объяснимые рекомендации и план действий. На старте не нужны электронные весы: массу можно вводить вручную, а интеграцию показывает явно обозначенный имитатор.

> Если сайт уже открылся на ноутбуке, Python переустанавливать не нужно. Для телефона переходите к разделу 6. GitHub хранит код; загрузка файлов сама по себе не создаёт общедоступный работающий сервер.

## Использованные технологии и инструменты

Приложение разработано на Python с браузерным интерфейсом на HTML, CSS и JavaScript. Для локального запуска требуется **Python 3.10 или новее**. Установка Node.js, MySQL и платных сервисов не требуется.

| Инструмент | Для чего используется |
|---|---|
| **Python** | Серверная логика: авторизация, проверка прав, обработка записей, согласование отчётов, аналитика и формирование Excel |
| **SQLite** | Хранение организаций, пользователей, записей отходов, отчётов, фотографий и истории действий |
| **HTML5** | Структура страниц, формы ввода и элементы интерфейса |
| **CSS3** | Оформление сайта и адаптация интерфейса для компьютера и смартфона |
| **JavaScript** | Работа интерфейса: запросы к серверу, фильтры, диаграммы, автосохранение черновика и обработка фотографий |
| **WSGI** | Интерфейс взаимодействия Python-приложения с веб-сервером |
| **python-qrcode** | Локальное создание QR-кодов форм организаций. Библиотека включена в проект |
| **Waitress** | Необязательный сервер для размещения приложения. Для обычного локального запуска не нужен |
| **unittest** | Автоматическая проверка приложения: реализовано 30 интеграционных тестов |
| **GitHub** | Хранение и распространение исходного кода, инструкций и презентационных материалов |

### Средства защиты данных

- **hashlib и PBKDF2-HMAC-SHA256** — хеширование паролей с индивидуальной солью.
- **Серверные сессии** — проверка входа и прав пользователя.
- **CSRF-токены** — защита операций изменения данных.
- **Параметризованные SQL-запросы** — безопасная передача значений в базу.
- **Триггеры SQLite** — дополнительная блокировка изменения записей принятых отчётов.

Доступ к организациям и действиям проверяется на сервере. Скрытие кнопки в интерфейсе не является единственным ограничением доступа.

## Сначала выберите режим

**Для закрытой работы запустите `start_private_windows.bat`. Для репетиции — `start_demo_windows.bat`.** `start_windows.bat` теперь предлагает выбор: 1 — закрытая база (по умолчанию), 2 — демо.

- **Закрытая база:** `instance/private.sqlite3`, один администратор, пароль задаёте вы при первом запуске. Вход: `admin` и ваш пароль. Пять организаций и их шаблоны уже есть, сотрудников и взвешиваний нет. Общие демо-пароли в этой базе не действуют.
- **Демонстрационная база:** `instance/demo.sqlite3`, синтетические записи и опубликованные демо-пароли из раздела 8. Только для репетиции. Не используйте её для реальных данных и не публикуйте как защищённый рабочий сервис.
- Кнопки входа под чужой ролью и пароль удалены со страницы входа. Пользователь вводит собственные данные.
- Новый пользователь нажимает «Подать заявку на доступ», выбирает организацию, задаёт логин, служебный e-mail и пароль. Пока администратор не одобрит заявку, вход запрещён. Заявка всегда создаёт только ответственное лицо, повышенную роль назначает администратор.

### Первые действия администратора в закрытой базе

1. Войдите как admin со своим паролем.
2. Откройте «Управление». Проверьте адреса/корпуса пяти организаций, уточните их.
3. Создайте и допустите отдельного проверяющего через «Создать и допустить сотрудника». Назначьте роль «Проверяющий». Используйте индивидуальный пароль.
4. Сотрудник подаёт заявку со страницы входа либо администратор создаёт его сам, назначая организацию и роль «Ответственное лицо».
5. В заявках администратора нажмите «Одобрить». До этого вход заявителя не работает. При отказе обязателен комментарий.
6. Новый вид отходов сотрудник добавляет прямо в форме. Он появляется в справочнике своей организации с пометкой «На утверждении». Администратор проверяет параметры и источник коэффициента. Пока вид не утверждён, отчёт с ним нельзя принять.
7. Итоговый месячный отчёт принимает **назначенная роль проверяющего**. Администратор также может выполнить эту функцию как совмещённую роль. Отдельной второй подписи администратора после принятия нет.
8. Для блокировки пользователя откройте его настройки → «Доступ: отключён». Существующие сессии отзываются. Отключение организации отзывает сессии её сотрудников. Назначенные ответственные видны в таблице организаций.

### Что изменилось в итоговой версии

- Пять шаблонов с полным перечнем, способами по умолчанию и итогами по каждому виду за выбранный день и месяц, включая «тара + кости» у ТПП.
- Видимое ответственное лицо в форме; редактирование только черновика своей организации.
- Возврат с комментарием оставляет статус «Возвращено». Кнопка «Начать исправление» переводит в черновик, затем повторная отправка. Все переходы записываются.
- Административная история заявок, назначений, блокировок и утверждения видов. Пароли в историю не записываются.
- Сравнение выбранного периода с предыдущим: полные месяцы, кварталы и годы; для произвольного диапазона — предшествующий диапазон той же длины. Отсутствие базы не подменяется 0%.
- Процент пригодных к переработке по признаку вида, отдельно условно пригодные и фактически переданные. Показаны неизвестные массы и коэффициенты.
- Фото к уже сохранённой черновой записи: кнопка «Прикрепить фото», JPEG/PNG. Браузер сжимает до 1280 px, убирает EXIF при пересохранении; сервер принимает максимум 500 КБ. После принятия фото также блокируется.
- QR формы организации: укажите доступный телефону адрес `http://IPv4:8000`, сформируйте QR. Он не содержит пароля и не даёт доступ без входа. Если сотрудник другой организации сканирует QR, права не меняются.
- Напоминание в отчёте и выгрузка срока в календарь ICS. По умолчанию срок — последний день месяца; фактический регламент нужно согласовать. Почта и Telegram автоматически ничего не отправляют.
- Excel дополнен отдельными журналами организаций с датой, видом, количеством, единицей, способом и ответственным.

### Обновление старого проекта

Самый простой путь — распаковать итоговый архив в **новую папку** и запускать её. Старую папку сохраните отдельно. В архиве нет вашей рабочей базы.

Если нужно перенести собственные записи, сначала остановите старый сервер и сделайте резервную копию через backup.py. Не подменяйте работающую базу. На копии старая структура расширяется при запуске: таблицы и поля добавляются без удаления записей. Старые принятые отчёты остаются заблокированными. Старые демо-пароли не становятся личными автоматически: для реальных данных используйте новую закрытую базу. Миграция проверена на прежней структуре, но перед переносом реальных данных нужна отдельная сверка копии.

## 2. Windows: запуск двойным щелчком

1. Откройте папку, где лежит `server.py`.
2. Дважды нажмите `start_windows.bat`, выберите 1 для закрытой работы или 2 для репетиции.
3. Оставьте открытым появившееся окно.
4. Откройте в браузере `http://127.0.0.1:8000`.
5. Войдите вручную: для закрытой базы admin и ваш пароль; для демо — учётные записи раздела 8.

Демо-BAT запускает сервер с `--demo --db instance/demo.sqlite3 --host 0.0.0.0`. Закрытый BAT вызывает launch_private.py и использует private.sqlite3 и личный пароль. При первом запуске введите пароль дважды: New password, Repeat password. Ввод скрыт, символы не появляются — это нормально. Если пароль короче 12 символов или подтверждение не совпало, программа попросит повторить. При первом запуске выбранная база создаётся, при повторном данные сохраняются. После завершения демонстрации вернитесь в окно сервера и нажмите `Ctrl+C`. Если BAT показывает `Press any key`, нажмите клавишу для закрытия окна.

Не открывайте `static/index.html` двойным щелчком. Live Server и GitHub Pages не заменяют Python API этого приложения.

## 5. Адреса: почему их несколько

Сайт работает на ноутбуке. Ноутбук может иметь Wi-Fi, Ethernet, VPN и виртуальные адаптеры. Программа перечисляет найденные IPv4, но не определяет, какой из них доступен вашему телефону.

| Адрес | Значение | Где использовать |
|---|---|---|
| `127.0.0.1` | «Этот компьютер», loopback | На ноутбуке, где запущен сервер |
| `localhost` | Имя, обычно указывающее на этот компьютер | Обычно работает на ноутбуке; при проблеме используйте `127.0.0.1` |
| `0.0.0.0` в команде | Слушать все IPv4-интерфейсы | Только параметр запуска, не адрес для браузера |
| IPv4 активного Wi-Fi | Адрес ноутбука в локальной сети | На ноутбуке и телефоне в достижимой сети |
| `169.254.x.x` | Автоматический link-local адрес | Для обычного Wi-Fi-подключения телефона обычно не подходит |
| `172.16.x.x`, `172.29.x.x` | Могут относиться к реальной или виртуальной сети | Проверять название адаптера, по цифрам нельзя выбрать |
| `192.168.128.1`, `192.168.56.1` | Могут быть виртуальными адаптерами или точкой доступа | Не считать адресом Wi-Fi без проверки |

Число `8000` после двоеточия — порт приложения. `http://` — протокол. На локальном демо вводите именно `http://`, не `https://`.

Вы НЕ обязаны пользоваться только `127.0.0.1`. На ноутбуке он удобен, потому что не меняется при смене Wi-Fi. На телефоне `127.0.0.1` указывает на сам телефон, где этот сервер не запущен.

## 6. Как открыть сайт со смартфона

### Способ A. Одна сеть Wi-Fi

1. Подключите ноутбук и телефон к одной доверенной сети Wi-Fi, не к разным гостевым сетям.
2. На ноутбуке запустите `py -3 server.py --demo --db instance/demo.sqlite3 --host 0.0.0.0`.
3. Сначала убедитесь, что на ноутбуке открывается `http://127.0.0.1:8000`.
4. Не закрывая сервер, откройте ВТОРОЕ окно PowerShell и выполните:

```powershell
ipconfig
```

5. Найдите блок **«Адаптер беспроводной локальной сети Беспроводная сеть»**, `Wireless LAN adapter Wi-Fi` или аналогичный с именем Wi-Fi. Пропустите адаптеры с отключённой средой, VirtualBox, VMware, vEthernet, VPN и Bluetooth.
6. В нужном блоке найдите **IPv4-адрес**. Обычно там же указан основной шлюз. Не берите адрес шлюза: нужен IPv4 самого ноутбука.
7. Допустим, IPv4 равен `192.168.1.34`. На телефоне в адресной строке браузера введите **`http://192.168.1.34:8000`**. Это пример: подставьте собственный адрес.
8. Войдите в демо-аккаунт. Ноутбук должен оставаться включённым, сервер запущенным.

Адрес также можно посмотреть без терминала: Параметры Windows → Сеть и Интернет → Wi-Fi → свойства подключённой сети → IPv4-адрес.

Сначала откройте тот же сетевой URL на ноутбуке. Если и там не работает, проверьте IPv4, порт и `--host`. Если на ноутбуке работает, а на телефоне нет, вероятны изоляция Wi-Fi, брандмауэр или различие сетей.

### Способ B. Ноутбук подключается к точке доступа телефона

1. Включите на телефоне «Точку доступа» / «Режим модема».
2. Подключите ноутбук к созданной сети Wi-Fi.
3. На ноутбуке заново выполните `ipconfig`: адрес мог измениться.
4. Используйте IPv4 Wi-Fi ноутбука с портом `:8000` в браузере телефона.

Не используйте IP телефона вместо адреса ноутбука. Некоторые телефоны ограничивают доступ к подключённым клиентам: в этом случае попробуйте способ C или домашний роутер.

### Способ C. Телефон подключается к точке доступа Windows

1. При поддержке компьютером включите Параметры → Сеть и Интернет → Мобильный хот-спот.
2. Подключите телефон к этой сети.
3. Выполните `ipconfig` на ноутбуке и найдите IPv4 адаптера созданного хот-спота. Здесь он может называться «Подключение по локальной сети*», а не Wi-Fi.
4. На телефоне откройте этот IPv4 с `http://` и `:8000`.

Не угадывайте адрес хот-спота по примеру. Он зависит от настройки Windows.

### Если телефон всё ещё не подключается

- Проверьте, что оба устройства действительно в одной сети, а телефон не использует только мобильный интернет. VPN может менять маршруты — для диагностики приостановите его, если это разрешено правилами вашей сети.
- В доверенной домашней сети/собственной точке доступа можно выбрать профиль Windows «Частная сеть». Не меняйте профиль общественной сети вуза на частный только ради демо.
- Откройте «Безопасность Windows» → «Брандмауэр и защита сети» → «Разрешить работу приложения через брандмауэр» → «Изменить параметры». Разрешите именно используемый `python.exe` для частной сети. Для Python 3.12 из примера путь: `C:\Users\Student\AppData\Local\Programs\Python\Python312\python.exe`.
- Если Python отсутствует в списке, выберите разрешение другого приложения и укажите свой `python.exe`. На управляемом компьютере может понадобиться администратор.
- Не отключайте брандмауэр целиком и не открывайте доступ для всех публичных сетей.
- Гостевая/университетская Wi-Fi-сеть может запрещать связь между устройствами даже при одинаковом имени сети. Используйте собственную точку доступа или обратитесь к администратору.
- Если браузер предлагает только HTTPS, вручную введите полный `http://IP:8000`. Не обходите предупреждения сертификатов: для локального HTTP сертификат не требуется.

Без вывода `ipconfig` нельзя определить, какой из адресов, напечатанных сервером, подходит вашему телефону. Для помощи достаточно блока активного адаптера с IPv4, маской и шлюзом. Пароли Wi-Fi присылать не нужно.

Локальный URL не является публичной интернет-ссылкой. Человек из другой сети обычно его не откроет. Для внешнего доступа нужен хостинг, раздел 10.

## 7. Если что-то не работает

| Ошибка / симптом | Причина и решение |
|---|---|
| `start_windows.bat is not recognized` | Не та папка. Выполните `dir`, перейдите в `atu-foodloop`. В PowerShell запускайте `.\start_windows.bat`. |
| `can't open file ... server.py` | Python работает, но `server.py` не в текущей папке. `Test-Path .\server.py` должен вернуть True. |
| `py` / `python` не распознаётся | Установите Python, включите PATH, заново откройте терминал. Попробуйте полный путь к python.exe. |
| Открывается Microsoft Store | Windows использует псевдоним вместо установленного Python. Попробуйте `py -3` или полный путь. |
| `WinError 10048`, address already in use | Порт занят. Остановите предыдущий свой сервер Ctrl+C либо запустите с `--port 8001`. |
| `WinError 10013`, доступ к сокету запрещён | Возможна политика/резервирование порта. Попробуйте 8001; на управляемом ПК обратитесь к администратору. |
| `ERR_CONNECTION_REFUSED` на ноутбуке | Сервер закрыт, завершился с ошибкой или выбран другой порт. Проверьте окно сервера. |
| На ноутбуке работает, на телефоне тайм-аут | Проверьте адаптер, общую сеть, `--host 0.0.0.0`, разрешение Python и изоляцию сети. |
| Пустая/неработающая страница после открытия HTML | Открыт файл напрямую. Запустите `server.py`, откройте HTTP-адрес. |
| `No module named waitress` | Вы выбрали `--production`. Выполните `py -3 -m pip install -r requirements.txt` либо для демо уберите `--production`. |
| Нет static/data или не загружается интерфейс | Архив распакован не целиком. Папки `static` и `data` должны быть рядом с `server.py`. |
| После обновления виден старый интерфейс | На компьютере Ctrl+F5. Проверьте, что сервер запущен из нужной копии проекта. |
| Демо-пароль не подходит | Возможно, открыта рабочая база или пароль изменён. `--demo` не перезаписывает существующую базу. Создайте новую отдельную демобазу, раздел 11. |
| Входит, но сразу выбрасывает на HTTP | Проверьте `COOKIE_SECURE`: для локального HTTP удалите эту переменную, если раньше включали её. |
| Запись не видна в обзоре/реестре | Отчёт ещё не принят. Отправьте, проверьте и примите его через reviewer. |
| После смены Wi-Fi телефон потерял сайт | Найдите новый IPv4 через `ipconfig`, обновите URL телефона. |
| После сна ноутбука сайт недоступен | Разбудите ноутбук, проверьте сервер и сеть. |
| В терминале возвращается `PS ...>` | Сервер завершился. Прочитайте ошибку выше приглашения и запустите заново. |

Для очистки переменной COOKIE_SECURE только в текущем PowerShell:

```powershell
Remove-Item Env:COOKIE_SECURE -ErrorAction SilentlyContinue
```

При обращении за помощью сообщите точную команду, текст ошибки, открываемый URL и результат `Test-Path .\server.py`. Не отправляйте собственные пароли и содержимое базы.

## 8. Как пользоваться сайтом

### Демо-вход

Все начальные демо-пароли: `FoodLoop2026!`.

| Логин | Роль и организация |
|---|---|
| canteen | Ответственное лицо столовой |
| coffee | Ответственное лицо кофейни |
| hotel | Ответственное лицо ATU INN |
| tpp | Ответственное лицо кафедры ТПП |
| thpp | Ответственное лицо кафедры ТХиПП |
| reviewer | Проверяющий всех организаций |
| admin | Администратор и проверяющий |
| director | Руководство, чтение и выгрузка |

Это роли сотрудников заказчика, а не состав команды проекта. Автор проекта — один человек.

### Запись и согласование

1. Войдите как canteen → Журнал → текущий месяц → Открыть журнал.
2. Выберите «Очистки овощей», введите 12,5 кг, проверьте дату и фактический способ обращения, сохраните.
3. Кнопка «Получить вес · имитатор» демонстрирует получение веса для видов в кг. Физические весы не подключены.
4. При необходимости добавьте новый вид. В дополнительных сведениях укажите причину и число порций конкретной партии.
5. Отправьте отчёт проверяющему.
6. В отдельном приватном окне войдите как reviewer → Проверка → откройте отчёт → Взять на проверку.
7. Верните с обязательным комментарием либо примите. Если в отчёте есть новый неутверждённый вид, сначала требуется утверждение вида администратором. Для демо возврата: «Уточните способ обращения с очистками».
8. Сотрудник видит «Возвращено» и комментарий, нажимает «Начать исправление», исправляет черновик и отправляет повторно. Проверяющий принимает.
9. Принятые данные появляются в реестре и обзоре. Принятый отчёт заблокирован для изменения.

Статусы: черновик, отправлено, на проверке, возвращено, принято. История сохраняет переходы и изменения. Исправление уже принятого отчёта отдельной корректировочной версией пока не реализовано.

### Разделы

- **Обзор:** три диаграммы, масса отходов, фактическая передача на переработку по записям, расчётная разница CO₂, несдавшие организации. Выберите период и нажмите «Применить».
- **Журнал:** формы, итоги по дню/месяцу/виду, отдельные кг и л. Оператор видит только свою организацию.
- **Проверка:** принятие, возврат и контроль сдачи.
- **Реестр:** только принятые строки. Фильтры по периоду, организации, виду и способу. Кнопка Excel выгружает сводку, детализацию и методику.
- **Действия:** рекомендации по прозрачным правилам, создание мероприятия со сроком, фиксация результата. Причину роста подтверждает человек.
- **Справочники:** виды и способы. Новые виды не получают автоматически придуманный коэффициент CO₂.
- **Администрирование:** создание организаций и пользователей, доступно admin. Новую организацию можно подключить без изменения кода.

Черновик формы сохраняется на этом устройстве с привязкой к пользователю/отчёту. Это не полноценная офлайн-синхронизация. На другом устройстве обновите страницу для получения изменений. Для разных ролей используйте обычное и приватное окно, иначе вход заменяет сессию.

Важное различие: `.gitignore` действует при использовании Git. При ручной загрузке через браузер он НЕ исключает файлы автоматически: выбирайте файлы сами.

### Способ A. Через сайт GitHub, без команд

1. Войдите на https://github.com .

14. Скопируйте адрес репозитория из браузера. Это ссылка на исходный код для жюри.

Если браузер не переносит папки, используйте GitHub Desktop или Git, не создавайте десятки файлов вручную. Через браузер можно загружать до 100 файлов за раз и до 25 MiB на файл; у проекта значительно меньше файлов, но смотрите размер новой презентации.

### Способ B. Через Git

Установите Git с https://git-scm.com/downloads , заново откройте PowerShell. Создайте ПУСТОЙ репозиторий на GitHub, затем в папке проекта:

```

Скопируйте HTTPS URL СВОЕГО репозитория через Code на GitHub. В следующей команде замените пример:

Пройдите авторизацию GitHub, если она появится. Обычный пароль аккаунта для Git по HTTPS не используется: применяйте браузерную авторизацию Git Credential Manager или поддерживаемый токен. Токен не добавляйте в URL и файлы.

Если push отклонён из-за существующих удалённых коммитов, не используйте force push. Для новичка проще клонировать репозиторий в новую папку, скопировать туда файлы проекта без instance и выполнить add/commit/push из этой папки.

git commit -m "Update documentation and presentation"
git push
```

Либо на сайте GitHub откройте README.md → карандаш → замените текст → сохраните коммит. Презентацию обновляйте через Upload files в папке docs с тем же именем. Если новое имя отличается, исправьте ссылку в README.

На GitHub нажмите Code → Download ZIP. Распакуйте в ДРУГУЮ папку, найдите server.py и запустите демо. Так вы проверите, что не забыли static/data. Не копируйте свою рабочую базу в скачанный проект.

### Почему GitHub Pages недостаточно

GitHub Pages обслуживает статические страницы. Это приложение использует Python API, сессии и SQLite, поэтому ему нужен Python-хостинг либо локальный сервер. Не включайте Pages в надежде, что заработает `server.py`. Для защиты можно запустить на ноутбуке, а исходный код показать по ссылке GitHub.

## 10. Рабочий сервер и Docker

Это вариант для администратора хостинга. Для обычной локальной демонстрации достаточно разделов 2–3.

Для публикации нужен сервер с Python/Docker, постоянным диском для базы, HTTPS-прокси и резервированием. Временный диск некоторых хостингов теряет базу после перезапуска. Развёртывание в аккаунт автоматически не выполнялось.

```powershell
py -3 -m pip install -r requirements.txt
```

Для чистой рабочей базы задайте `ADMIN_PASSWORD` не короче 12 символов в окружении, `FOODLOOP_DB` как путь на постоянном диске. В PowerShell можно ввести пароль без сохранения его в истории команд:

```powershell
$securePassword = Read-Host "Новый пароль администратора" -AsSecureString
$env:ADMIN_PASSWORD = [System.Net.NetworkCredential]::new("", $securePassword).Password
$env:FOODLOOP_DB = Join-Path (Get-Location) "instance\production.sqlite3"
py -3 server.py --production --host 0.0.0.0 --port 8000
```

Первый вход: admin и заданный пароль. Пять организаций и шаблоны уже есть, учётных записей сотрудников и записей нет: создайте сотрудников или одобрите заявки. Не добавляйте `--demo` для рабочих данных. Установка нового ADMIN_PASSWORD не сбрасывает пароль в существующей базе.

`COOKIE_SECURE=1` включайте только за работающим HTTPS-прокси. На локальном HTTP эта настройка мешает входу. Если приложение работает за прокси, сохраните корректные Host/Origin для проверки запросов. Секреты храните в настройках хостинга, не в Git.

Docker, после установки Docker и задания ADMIN_PASSWORD в окружении:

```bash
docker build -t atu-foodloop .
docker run --rm -p 8000:8000 -v foodloop-data:/app/instance -e ADMIN_PASSWORD atu-foodloop
```

Этот вариант публикует HTTP-порт. Для реального доступа настройте HTTPS перед контейнером и передайте `-e COOKIE_SECURE=1`. Для Docker-демо:

```bash
docker run --rm -p 8000:8000 -v foodloop-demo:/app/instance atu-foodloop python server.py --production --demo --host 0.0.0.0
```

Не запускайте несколько независимых контейнеров с разными SQLite-базами как одну систему. При росте нагрузки нужна отдельная оценка архитектуры.

## 11. Данные, резервные копии и тесты

База появляется в `instance/foodloop.sqlite3`. Она хранит записи, пользователей и сессии. Закрытие браузера и перезапуск программы её не стирают. Не заменяйте и не удаляйте instance при обновлении README/презентации.

Создание согласованной резервной копии из папки проекта:

```powershell
py -3 backup.py
```

Результат находится в `instance/backups`. Резервные копии также не публикуйте в GitHub. Если использовали нестандартный `--db`, укажите тот же путь в FOODLOOP_DB перед backup.py.

Для восстановления сначала остановите сервер, сохраните текущую папку instance отдельно и используйте проверенную копию с учётом SQLite WAL. На рабочем сервере поручите восстановление администратору. Просто копировать один работающий файл базы, игнорируя WAL, ненадёжно.

Новая отдельная база для репетиции, без удаления предыдущих данных:

```powershell
py -3 server.py --demo --db instance/rehearsal.sqlite3 --host 0.0.0.0
```

Для следующей чистой репетиции выберите новое имя, например rehearsal2.sqlite3. Принятый отчёт в старой базе останется заблокированным.

Автоматические интеграционные тесты:

```powershell
py -3 -m unittest discover -s tests -v
```

Они используют временные тестовые базы. Проверяют роли, согласование, блокировку, единицы, CO₂, Excel, дубли и фильтры. Прохождение тестов не заменяет проверку физического телефона в вашей сети.

Справочник содержит 19 видов и 7 способов из материалов задания. Исторические массы синтетические, это не реальные измерения АТУ. Физические весы, OCR/распознавание вида по фото, почтовые уведомления и полноценная офлайн-синхронизация пока отсутствуют. Прикрепление фото и QR реализованы.
