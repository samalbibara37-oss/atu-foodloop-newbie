# Сценарий защиты FoodLoop ATU
Автор: Самал Бибара. Всё ниже — репетиция с синтетическими данными.

1. Запустить start_demo_windows.bat. Вручную войти canteen / FoodLoop2026! на телефоне, reviewer / тот же пароль в отдельном приватном окне ноутбука. Для admin использовать ещё один отдельный профиль/браузер.
2. Открыть текущий месяц. Показать шаблон организации с перечнем и итогами по выбранному дню/месяцу.
3. Внести 12,5 кг очисток, 2 кг картона. Можно прикрепить фото к сохранённой записи. Показать числовую клавиатуру телефона и автоматические дату/ответственного.
4. Добавить «Чайная заварка», кг, органические. Она появляется в справочнике с отметкой «На утверждении». Внести 1,25 кг.
5. Отправить месячный отчёт. Проверяющий берёт на проверку, возвращает с комментарием «Уточните способ обращения с очистками».
6. Сотрудник видит «Возвращено», нажимает «Начать исправление». В черновике исправляет запись, повторно отправляет.
7. Показать, что принятие невозможно до утверждения нового вида. Администратор в Управление → Новые виды → Проверить параметры утверждает чайную заварку, оставляет неизвестный коэффициент пустым.
8. Проверяющий берёт и принимает отчёт. История показывает весь путь. Записи и фото заблокированы.
9. В реестре выбрать организацию/вид, показать принятые строки. В обзоре три графика, долю пригодных и сравнение периодов. Демо-массы не выдавать за результат АТУ.
10. Выбрать прошлый квартал, все организации, скачать Excel: сводка, детализация, методика и журналы пяти организаций.
11. В Управление показать заявки, отключение пользователей, ответственных и аудит. Для чистого примера заявка со страницы входа не даёт войти до одобрения. Письмо автоматически не отправляется.
12. Показать QR: ввести IPv4 ноутбука из Wi-Fi. Паролей в QR нет. На ноутбуке 127.0.0.1 работает, на телефоне нужен сетевой адрес.

## Репетиция без потери предыдущей базы
`py -3 server.py --demo --db instance/rehearsal.sqlite3 --host 0.0.0.0`
Для следующей чистой репетиции выбери новое имя. Принятый текущий отчёт не разблокируется.

## Текст на демонстрацию
«Сотрудник заполняет форму своей организации. Система считает день и месяц. Новый вид можно предложить на месте, его параметры проверяет администратор. Проверяющий возвращает отчёт с замечанием. Сотрудник начинает исправление и отправляет заново. После принятия сведения попадают в реестр, графики и Excel. На этих данных мы проверяем меры по снижению потерь».

## Вопросы
- Кто принимает отчёт? Проверяющий. Администратор управляет допуском и справочником, может совмещать роль проверяющего.
- Почему демо-пароль общий? Только для репетиции. Закрытая база создаётся отдельно, там нет демо-пользователей и общих паролей.
- Где ИИ? Он помогал разработке. Рекомендации продукта объяснимые, по правилам. Фото не распознаются автоматически.
- Эффект доказан? Нет, это сценарная модель. Нужен пилот с реальными измерениями и сопоставимым числом порций.
- Что с принятой ошибкой? MVP блокирует отчёт. Корректировочные версии — дальнейшая разработка; ручное изменение принятой базы недопустимо.
